#definition 

summary: defining the terms technical, cognitive and intent debt

technical debt: problems in code
- makes code harder to change
cognitive debt: the team's lack of understanding of the codebase
- makes systems hard to understand
intent debt: lack of system design goals and constraints
- makes it difficult to know what the system is supposed to do
--- 

the definition of technical debt is vague. the linked citation from Cunningham explains it well: "Shipping first time code is like going into debt" (Cunningham, 1992). the more time spent on the code, you're gooing more and more into debt. the debt is repaid with a rewrite. the context of the article was using objects through Smalltalk, an object oritented langauge, to allow for easier revisions to the code. it was proposed as a balance between waterfall method (expensive, getting it right from the first time) and shipping first time code.
